# 前言

先看一段程序。

```cpp
#include <iostream>
#include <string>

int main() {
    std::string line;
    while (true) {
        std::cout << "> ";
        if (!std::getline(std::cin, line)) break;
        if (line == "quit") break;
        if (line == "hello") {
            std::cout << "你好，世界\n";
        } else if (line == "time") {
            std::cout << "现在该干活了\n";
        } else {
            std::cout << "不认识的命令：" << line << "\n";
        }
    }
    return 0;
}
```

它只有二十来行，运行起来是一个不断等待输入的小窗口。你输入 `hello`，它回一句问候；输入 `time`，它回一句提醒；输入 `quit`，它退出。

这本书要从这段程序出发，一步一步把它变成一个大型软件的样子：功能由不同的文件提供，新功能可以单独编译、单独发布，第三方写的模块能在不重新编译主程序的情况下装进来，某个模块出错时主程序还能活着。

这个过程会经过很多次改造。每改造一次，只增加一个概念，并且给出能编译、能运行的代码。你不会看到“定义一个接口然后动态加载实现”这种一句话带过的说法，因为那句话背后至少有六件事要处理，每一件都值得单独讲一章。

## 写给谁

这本书假定你学过一門编程语言的基础语法，知道变量、函数、循环、数组大概是什么，用 C++ 写过程序，哪怕只写过一个控制台小程序。你不需要懂 Java，不需要学过操作系统，也不需要知道编译原理。

书里会反复出现一些工程词，比如编译、链接、动态库、进程、序列化、事件、钩子。这些词第一次出现时都会先用日常经验解释，再放进代码里。如果某个词你在别处看过但一直没弄懂，这本书希望把它讲到你能够自己复述出来。

## 为什么用 C++

C++ 有一个好处，也有一个坏处。

好处是它把很多被高级语言藏起来的东西摆在明面上。你可以看到头文件和源文件是分开的，可以看到编译和链接是两个步骤，可以看到动态库在运行时才被加载。这些机制在 Java、C#、Python 里也有，但被包装得更深，初学时不容易看清。

坏处是 C++ 的细节多，容易写出崩溃的程序。书里会尽量把代码控制在标准库范围内，不引入第三方框架，每一段都尽量短。涉及平台差异的地方，会分别给出 Windows 和 Linux 的写法。

## 路线

全书分四篇，十二章。

第一篇从那段二十行的程序开始。先把它拆成函数，再拆成多个文件，然后编译成动态库，最后让主程序在运行时把动态库读进来。这一篇结束时，你已经有第一个真正意义上的插件。

第二篇处理边界。插件和主程序之间要有合同，合同要能版本化；主程序不能认识每一个插件的名字，要用注册表和扩展点；插件之间要通过事件和钩子协作；插件崩溃时，主程序要能活下来。

第三篇把它变成工程。用一条命令生成新组件的骨架，让组件可以脱离主程序单独开发和测试，再打包、签名、分发、更新。

第四篇收拢。把前面所有代码拼成一个可以照着搭起来的最小系统，给出完整目录、构建命令和一份继续演进清单。

## 读法

书里的代码都可以直接编译。建议你至少动手跑一遍前三章的代码，因为“动态库被加载进来”这件事，看文字和亲眼看它跑起来，理解程度差别很大。

如果某一段代码暂时看不懂，可以先跳过细节，看它前后的中文说明，知道这段在整个流程里负责什么，再回头逐行读。工程的难点往往不在某一行语法，而在于很多行怎么配合。

准备好了的话，从第一段程序开始。
