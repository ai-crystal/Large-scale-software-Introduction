# 第 1 章 二十行程序

本章的完整代码和编译说明在 `codes/ch01/`。

## 1.1 先让它跑起来

把下面这段代码保存成一个文件，名字叫 `main.cpp`。

```cpp
#include <iostream>
#include <string>

#ifdef _WIN32
#include <windows.h>
#endif

int main() {
#ifdef _WIN32
    SetConsoleOutputCP(CP_UTF8);
#endif
    std::string line;
    while (true) {
        std::cout << "> ";
        if (!std::getline(std::cin, line)) break;
        if (line == "quit") break;
        if (line == "hello") {
            std::cout << "你好，世界\n";
        } else if (line == "time") {
            std::cout << "现在该干活了\n";
        } else {
            std::cout << "不认识的命令：" << line << "\n";
        }
    }
    return 0;
}
```

在 Windows 上，如果你装的是 Visual Studio，打开“开发者命令提示”窗口，进入这个文件所在的目录，输入：

```bat
cl /EHsc /std:c++17 main.cpp
```

会得到一个 `main.exe`，双击或者在命令行里输入 `main.exe` 就能运行。

如果你用的是 MinGW 或者 Linux，输入：

```bash
g++ -std=c++17 main.cpp -o app
./app
```

运行之后，屏幕上会出现一个 `>`，等你输入。输入 `hello` 回车，它回答“你好，世界”；输入 `time` 回车，它说“现在该干活了”；输入别的，它说不认识；输入 `quit`，程序结束。

这一章剩下的部分，就是把这段代码一行一行拆开，看清楚它到底在做什么。别急着往后翻，先确认你能把它跑起来。

## 1.2 逐行读代码

### 开头的几个 include：把工具箱拿进来

```cpp
#include <iostream>
#include <string>

#ifdef _WIN32
#include <windows.h>
#endif
```

`#include` 的意思是“把另一个文件的内容搬到这里”。尖括号里的 `iostream` 和 `string` 是 C++ 标准库自带的两个工具箱。

`iostream` 里装着输入输出的工具，屏幕打印、键盘读取都要用它。`string` 里装着字符串工具，也就是“一串文字”。

`#ifdef _WIN32` 到 `#endif` 之间是条件编译：只有在 Windows 上编译时，才会把 `windows.h` 拿进来。这个头文件提供 `SetConsoleOutputCP`，用来设置控制台编码，1.4 节会解释。在 Linux 或 macOS 上，这三行会被跳过，不参与编译。

### main：程序的入口

```cpp
int main() {
```

`main` 是一个特殊函数。操作系统启动一个程序时，会先找到这个名字，从它开始执行。`int` 表示这个函数最后要返回一个整数，`()` 表示它不接收参数。

你可以把 `main` 想成一家店的正门。客人从正门进来，店里的事从这里开始；正门关着，店就没法营业。

### 准备一个装文字的盒子

```cpp
    std::string line;
```

这一行声明了一个变量，名字叫 `line`，类型是 `std::string`，也就是“一串文字”。它现在是一个空盒子，等着装用户输入的内容。

`std::` 是一个前缀，表示“这个东西来自标准库”。C++ 标准库把所有东西都放在 `std` 这个命名空间里，避免和你的变量重名。写起来麻烦一点，但不容易撞车。

### 不停地问

```cpp
    while (true) {
```

`while` 是循环。括号里的条件为真，就重复执行大括号里的内容。`true` 永远为真，所以这是一个“一直转下去”的循环，直到遇到 `break` 才停。

大型软件的主界面也是这样的循环：等用户操作，处理，再等下一个操作。这个循环有个名字，叫**事件循环**。现在你看到的版本很简单，只有键盘输入；真实的软件还要处理鼠标、窗口大小变化、网络消息，但骨架是同一个。

```cpp
        std::cout << "> ";
```

`std::cout` 是标准输出，默认就是屏幕。`<<` 把右边的东西送到左边。这一行在屏幕上打印一个 `>` 和一个空格，作为提示符。

```cpp
        if (!std::getline(std::cin, line)) break;
```

`std::cin` 是标准输入，默认就是键盘。`std::getline(std::cin, line)` 从键盘读一整行，放进 `line` 这个盒子里。

它还有一个返回值，表示“读到了没有”。读到返回真，读不到返回假。前面的 `!` 是“取反”，所以整句的意思是：如果没读到，就跳出循环。

什么时候会读不到？用户按下 Ctrl+Z（Windows）或者 Ctrl+D（Linux），表示输入结束；或者输入流出了别的问题。没有这一行，程序在输入结束时可能陷入死循环。

```cpp
        if (line == "quit") break;
```

如果用户输入的是 `quit`，跳出循环，程序往下走到结尾。

`==` 是比较，判断两边是否相等。注意是两个等号，一个等号是赋值，这是初学者最容易写错的地方。

```cpp
        if (line == "hello") {
            std::cout << "你好，世界\n";
        } else if (line == "time") {
            std::cout << "现在该干活了\n";
        } else {
            std::cout << "不认识的命令：" << line << "\n";
        }
```

这是一串条件判断。先看是不是 `hello`，是就打印问候；不是再看是不是 `time`，是就打印提醒；都不是，就打印“不认识”，并把用户输入的内容原样带出来。

`\n` 是换行符。没有它，下一次输出会接在同一行后面。

### 关门

```cpp
    return 0;
}
```

`return 0` 表示程序正常结束。操作系统会收到这个 0，认为“一切正常”。如果程序因为错误退出，通常返回一个非零的数字，方便脚本或者启动器判断。

## 1.3 编译到底做了什么

你输入的那条 `cl` 或者 `g++` 命令，背后做了两件事。

第一件叫**编译**。编译器读 `main.cpp`，检查语法对不对，把每一行翻译成计算机能执行的指令，生成一个中间文件。Visual Studio 生成的是 `main.obj`，MinGW 和 Linux 生成的是 `main.o`。

第二件叫**链接**。你的程序用到了 `std::cout`、`std::string` 这些东西，它们的实现不在你的文件里，而在标准库里。链接器负责把你的 `main.obj` 和标准库拼在一起，生成最终的 `main.exe` 或者 `app`。

可以借做饭来理解。编译是把菜谱翻译成一份厨房能执行的工序单，链接是把工序单和厨房里现成的调料、厨具配齐。工序单写得再对，缺了调料也做不出菜。

现在你不需要记住所有细节，只要知道两件事。第一，源文件不是直接运行的，中间要经过翻译。第二，你的程序可以引用别处写好的东西，链接器会把它们接上。

第 2 章会把这两个步骤拆开，让你亲眼看到中间文件长什么样。

## 1.4 如果你的中文显示成乱码

Windows 的控制台默认用 GBK 编码显示文字，而 C++ 源文件现在普遍是 UTF-8。编译器把源码里的中文按 UTF-8 编进程序，控制台却按 GBK 去解释，屏幕上就会出现“浣犲ソ”这样的乱码。

代码里那三行 `SetConsoleOutputCP(CP_UTF8)` 就是解决这个问题的。它在程序启动时把控制台的输出编码切到 UTF-8，和源码保持一致。

如果你在 Linux 或者 macOS 上编译，这几行会被 `#ifdef _WIN32` 挡掉，不参与编译。那些系统的终端默认就是 UTF-8，不需要额外设置。

本书后面所有示例都做了同样的设置，代码里不再重复解释。

## 1.5 它已经有一个内核的雏形

这段程序虽然小，但已经包含了三个零件，后面所有章节都在扩展它们。

**一个循环。** `while (true)` 不停地等待输入、处理、输出。这是所有交互式程序的心脏。

**一张命令表。** 现在这张表是 `if` 和 `else if` 堆出来的：`hello` 对应一段代码，`time` 对应另一段。表在代码里，写死了。

**一个输出通道。** `std::cout` 把结果送到屏幕。现在只有一个通道，将来可能有窗口、日志文件、网络。

把这三个零件抽出来看，一个插件系统的骨架就浮出来了。循环是宿主的主循环，命令表是注册表，输出通道是宿主提供的能力。后面要做的，是把写死的命令表变成可以运行时添加的，把一段段代码从 `main` 里搬出去，让它们可以单独编译、单独替换。

## 1.6 三个问题

这段程序能跑，但每加一个功能，你都会难受一次。

**加一个命令，要改主程序。** 想加一个 `date` 命令，你得打开 `main.cpp`，在 `if` 链里再插一段，重新编译整个程序。如果这个程序是别人装的，你还得让所有人重新下载。命令越多，`main` 越长，最后没人敢动。

**所有代码在同一个文件里。** 现在只有二十行，无所谓。等它变成两千行，函数、变量、输出混在一起，找一个地方要翻半天。更麻烦的是，你没法把某一部分单独拿出去测试，因为它依赖 `main` 里的局部变量。

**一个错误会带走整个程序。** C++ 没有 Java 那样的自动内存检查。一个数组越界、一个空指针、一次除零，都可能让程序直接崩溃，用户没保存的东西一起消失。如果所有功能都在一个程序里，任何一个功能的错误都是整个软件的错误。

这三个问题对应三个改造方向：**把代码搬出去、把加载变成运行时、把错误关进笼子**。

第一篇先解决第一个和第二个。第三个留到第 7 章。

## 1.7 下一步

改造从最小的一步开始：把 `hello` 和 `time` 这两段处理逻辑，从 `main` 里搬出来，变成两个函数。

这一步看起来只是“让代码整齐一点”，但它会带来一个关键的变化：函数有了名字，就可以被别的地方调用；可以被别的地方调用，就有可能被别的文件调用；能被别的文件调用，就有可能被编译成独立的模块。

从函数到文件，从文件到动态库，从动态库到插件，这条路是一步步走出来的。下一章走第一步。
